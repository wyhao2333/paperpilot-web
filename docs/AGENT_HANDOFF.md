# 给 Ubuntu 电脑 Agent 的交接

## 目标

在 Ubuntu 24.04 单机用 Docker Compose 部署 PaperPilot Web，再接入用户已有的 Cloudflare Tunnel。建议普通 16GB 内存电脑，程序不依赖 GPU。

## 源码边界

使用本 Web 应用的独立仓库。原 Zotero 插件和 ANNA_APP 不需要部署。

默认正式入口是 `python -m paperpilot`，Docker 已配置。`tests/ui_server.py` 仅用于模拟接口的浏览器测试，绝不能作为正式入口。

## 执行顺序

1. 读 README、AGENTS.md 和 DEPLOY_UBUNTU.md，检查 Docker、Compose、磁盘和端口。
2. 在用户指定路径克隆独立仓库，复制 `.env.example`，按本机测试模式启动。
3. 首先记录实际 Docker 构建结果和 `/api/health` 响应，再用离线命令创建唯一的初始管理员；密码由用户在本机输入。Compose 禁止自动登录，不开放注册。迁移数据先确认已有管理员，再决定设置密码或创建账号。
4. 用户提供测试 PDF，在页面填写接口密钥。不要从其他项目、聊天记录或全局目录搜集密钥。
5. 验证 PDF 段落、公式图片、矢量图与表格、真实翻译、笔记与重启恢复。先按段试译；AI 重排需用户明确点击，可能消耗其接口额度。
6. 使用用户确认的子域名和现有 Tunnel 配置公网入口，随后设置 HTTPS origin 和 Secure cookie。
7. 用两个账号和手机网络确认隔离与实际连通性，保存一份不含密钥的部署记录。

## 数据与运行约束

- SQLite + 本地文件卷；一个应用实例，两个文献后台任务槽与一个独立问答任务槽，PDF 解析子进程串行。翻译每个任务使用有界工作池；相同翻译连接共享并发槽，HTTP 连接池支持 40 个连接。
- 数据卷里的 `secret.key`、`pdfs/`、`media/` 与数据库一起备份；旧解析版本和译文在数据库 `document_versions` 中可恢复。
- 不自动切换翻译服务，不隐藏失败段落。
- 翻译按公式 ID 的多重集检查（不能缺少、重复或新增），允许中文正常语序引起的公式位置调整；不可再用原顺序严格相等误伤比较句。损坏时自动启用结构化文字片段、本机回填公式；AI 段落含至少 8 个公式标记时先分块使用本地短标记，逐块严格校验后恢复为原 ID，失败再走结构化片段。返回字段缺失、多余、含标记、上下文公式标签或格式不合法时逐片翻译文字。补救仅发送目标文本与术语，不给小模型重复的整段 SOURCE，以防上下文复制。修复兼容现有成功缓存，保留原译文；不要把缺失公式随意追加到段尾，也不要关闭完整性校验。结构校验不能保证模型翻译语义准确，仍须原页核对。
- 原 PDF 支持手动缩放和覆盖窗口的放大预览。使用 PDF.js 重新渲染矢量页，后台画布上限约 1600 万像素，避免普通笔记本高倍缩放时内存膨胀；放大预览可 Esc 退出，翻页和高亮继续使用同一阅读状态。
- 默认 `DAILY_TEXT_LIMIT=0`，仅统计发送字符和调用次数，不设置本站每日字数限额。迁移旧 `.env` 时检查旧值；不要通过清空 `usage` 表解决限额。服务商余额、上下文窗口和限流仍由服务商决定。
- AI 重排采用紧凑段首行编号和智谱 / DeepSeek JSON 模式，服务端从原文构造完整段落；校验失败最多纠正一次，全部通过后才替换。`reflow_cache` 保存已校验批次，重试复用相同原文及模型结果，成功后清理缓存。问答支持中文主题匹配英文章节，失败问答不进入后续模型历史。
- 智谱 1305 是模型服务繁忙，1302 是账号频率受限，1113 是欠费，不要要求用户因 1305 重新填写密钥。临时 429 和服务端 5xx 会有限次数退避重试，不自动换模型。
- 不把模拟翻译、合成 PDF 或 Windows 通过的测试当作真实 API / Ubuntu 成功的证据。
- 默认禁止内网自定义 API，只有用户确实需要且信任成员时开启 `ALLOW_LOCAL_API`。
- v0.2 基于坐标重排正文，用原页片段显示公式和图表；公式不是 LaTeX。AI 只选择分段，服务端校验原文行完整与顺序。没有重型 OCR、共享文献、公开注册或 Zotero 同步。
- DeepSeek 默认 `deepseek-flash`；智谱默认 `glm-4-flash`。按实际账户权限测试，不擅自替换付费模型。各服务商密钥独立保存，禁止跨服务商复制密钥。
- `ai_tasks.translation` 与 `ai_tasks.chat` 分别保存服务商和模型选择；chat 同时用于 AI 重排。凭证从 `ai_profiles` 解析，旧 `ai` 配置作为旧版本兼容默认。旧数据在明确分配任务前保持原配置；API Key 不能在响应中回传，换端点时不能继承旧 Key。
- `translation_concurrency` 默认 6、范围 1～16；机翻另有较低并发上限。遇到服务商限流按账号控制台权限调低，不依据模型名称推断高并发权益。取消任务会保留已发出请求的结果，并阻止新请求和后续重试。
- 可分别选择翻译 `glm-4-flash`、问答 / 重排 `deepseek-flash`，实际由部署后的用户自行填写连接与密钥；仓库不包含本地账户或配置。问答 Enter 发送，Shift+Enter 换行，中文输入法选词期间不会发送。
- 不添加定时任务、自动唤醒或无人值守发布，除非用户另行提出。

## 输出

向用户报告仓库 commit、部署路径、容器状态、本机地址、实际公网地址、数据卷、真实接口验证结果和仍未验证的项目。不要输出任何密码、API Key、Tunnel token 或配置文件的完整内容。
